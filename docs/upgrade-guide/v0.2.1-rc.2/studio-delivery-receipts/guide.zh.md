# 升级 Studio 交付回执

## 变更

Studio 打包复用已通过的最终内容验收，检查文件清单与变更元数据，移动后检查一次链接，只为实际改动产物更新指纹。收尾不再遍历计算所有交付文件的哈希，也不在清理后重复完整内容验收。前面的原件与语义检查继续生效。此方案发现普通变更，不作为密码学完整性证明。

## 迁移

1. 保留课程文档和已留存的验收记录。
2. 对仍在生成且只有版本 1 final 快照的课程，在 package 前执行一次现有交付阶段的 final-check。
3. 对已完成打包且已有通过的“打包检查.json”和“打包回执.json”的课程，下次 packaged 检查会在文件未变时升级回执，无需恢复已清理的中间文件。旧快照保存在“_工作区/链接校验报告.v1.json”；晚于通过报告的文件变更会阻止升级。
4. 确认“_工作区/打包检查.json”包含 passed: true 与 integrity: metadata-v1。课程原文变更仍需重新完成内容验收。
