# 核心知识点卡片规范

**编写前置门：** 先生成完整、非空的 `知识内容.md`，并运行 `assemble_knowledge.py --course COURSE --check`。未通过不得编写本阶段产物。用户明确要求 AI 补全也必须先建知识库；禁止只凭目录/常识跳过知识库直接写作。


根据用户提供的《核心知识点卡片规范》整理，使用用户指定文件名 `核心知识点.md`。卡片用于独立复习，不能代替完整讲义。

## 抽取、粒度与索引

从知识索引及 `知识内容.md` 的对应分片抽取核心候选，依据学习目标、前置枢纽作用、材料强调及题型覆盖证据筛选。不能将材料未强调的内容凭感觉标为“必考”，没有频次数据不虚构频次。

一卡为可独立复述、可单独考核的最小完整知识单元。定义与直接判据可合并，条件必须与公式同卡，纯记号放术语表。终端知识也可成卡；没有后续知识如实写无，不为满足模板编造关联。

卡片使用规范中文标题和别名，按讲义首次出现次序排列。一张卡一个稳定 ID，格式 `KP-章号-节号-序号`（各至少两位），重排后 ID 不变。每张卡是一个 `BL-KP` 区间，标题后第一行写入口锚点 `KP-01-01-01 ^KP-01-01-01`，**不要**在卡片末尾再写 `^{KP-ID}`；跨文件引用由脚本渲染为 `[[核心知识点#^KP-01-01-01|知识名称]]`，不使用 ../ 相对路径。

卡片的关系权限是最窄的：出边只能连 **canonical K**（`TEACH.summarizes`）、**active EX**（`TEACH.practice`）、**相关讲义 L**（`TEACH.lesson`，章级）与**前置/后续/关联卡片**（`DEP.prerequisite`、`NAV.next`、`NAV.related`）。不连来源单元、Path、START 或 IDX 容器。

**正文链接规则（写前先读）**：

1. 正文**禁止**手写计划外的任何 wikilink（如相对路径、`.md` 后缀、heading 锚点、其他实体链接），违规报 `MANIFEST_LINK_VIOLATION` / `KP_TARGET_FORBIDDEN`。
2. 引用前置卡、后续卡、关联卡、相关讲义、覆盖知识、练习时**必须**使用 `_工作区/核心卡片计划.json` 里 `plan.links.*` 的 canonical 字面量，并在**名字所在位置**就地链接，不允许只写名字：`先学：[[核心知识点#^KP-02-01-01|特征值]]`。相关讲义用 `plan.links.lessons`（章级 `#^L-0x`），练习用 `plan.links.exercises`（reserved 状态不是有效目标）。
3. 提及必链实体（前置/后续/关联卡、相关讲义、本卡覆盖知识）的名称或 ID 却没有链接时报 `UNLINKED_REFERENCE`：显式 ID 与必链名单内的名称是 error，术语型名称是 warning。
4. **不链接转写文件**：不得出现 `[[资料转写/...]]` 或指向 SRC 实体的链接，报 `SOURCE_LINK_FORBIDDEN`；来源一律用文字标注（文件名、章节、页）。
5. 卡片之间的前置关系来自知识前置（`K.prerequisites`），关联关系来自候选行的 `related_concepts`；都由脚本推导，主代理不手工补写逆向边。关系区仍由脚本渲染，正文内联链接是同一条关系的散文呈现。

开头索引表：卡名、ID、所在章-节、能力层级、难度、掌握度、直达链接。每卡元数据表包含名称、别名、英文、ID、覆盖知识 ID、课程、章节、能力层级、难度、掌握度、置信度、来源定位和更新日期。单文件不为每张卡重复放置文件级 YAML front matter。

## 检索与纠错设计

卡片服务复习，与首次学习的讲义分工。按计划 `teaching_designs` 与 `teaching_units` 选择适合学科和学习目标的检索对象；不复制单元完整推理、例题、前置诊断和迁移任务。跨章合卡围绕同一可考核核心，不把多个模板全文叠加。

卡片必须保留可复述的定义/规则/证据/动作要领及必要条件与边界、先尝试后核对的检索任务与答案/量规、针对易混的辨别或纠错线索、真实回补与应用入口、掌握证据。任务可共享讲义的 active EX，提示直接定位，不重抄题目和解析；卡内检索提示与核对分区。未设 active EX 时用本卡检索任务验证，不造不存在的练习链接。

直观案例、反例、微型步骤示范、术语对照仅在完成检索或纠错确有需要时补充。必要前置可用链接和激活线索，已有掌握证据时不重教。来源、更新与真实限制不得省略。没有公式或唯一答案时采用判据、证据、表达提示、量规或可接受方案。

不设字数与固定题数要求。删去同义复述和与检索目标无关的延伸，必要条件与反馈不能为求短而丢失；详细理解回讲义。重复只有承担间隔检索、条件辨识或新情境应用时才保留。

## 一致性与掌握度

所有卡片知识必须已在讲义解释。卡片与已核查正文冲突时回到材料核实，修正分片/知识库、正文或卡片并记录，不机械相信某个文件。不能把新补充只留在卡片中。

掌握度：未接触 → 能听懂 → 能复述 → 能做题 → 能应用 → 能迁移。没有学习证据时保持未接触/低置信度。自评不能单独升级；一次独立证据最多升一级；与例题高度相似的回答不能证明迁移。连续两次独立失败或核心概念反转时降一级并记录原因；短暂遗忘先回顾复测，不清零。不同能力维度可分别记，前置缺口同时关联根因卡。

卡片验收：规范名称与唯一 ID、真实依赖、准确定义/条件、可独立完成的检索及核对反馈、有效辨误/回补、真实入口与来源、掌握证据。缺必要知识、条件或检索反馈应返工；不把可选示范和反例数量作为验收门槛。


## 全局收口与快照

显式 `bounded-v1` 的局部卡片候选须按 [有界生成接入](bounded-pipeline.md) 取得 cards 阶段独立审核并留存证明，再执行本节收口。默认模式保持主代理写作。

仅主代理在所有 lesson `commit` 完成且 `lesson_tasks.py check` 有效后执行，不派卡片子 Agent，讲义写作阶段不分配最终卡片 ID。主代理逐章抽取精简候选，写 `_工作区/核心候选.jsonl`，按知识 ID、定义/公式关系与 concept_key 统一消除同义重复。不要宣称写文件后能清空主对话；按需读取片段，避免重读所有讲义。

讲义有效性按**教学内容指纹**（剥离脚本渲染的关系区与锚点）判定：`finalize` / `rebuild` 重渲关系区不会让已提交讲义失效，教学正文或其有效输入（包括单元设计和选中模板）变化才会。

core_cards.py prepare 只对主代理确认的归一键分组，不能自动证明语义相同。它分配稳定 KP ID、回写知识索引与双链；主代理按照计划与 `assets/templates/core-card.md` 形成核心知识点.md，链接（边界、锚点、关系区）始终由脚本渲染：写完卡片先运行 `core_cards.py finalize` 完成卡片收口，再运行 `obsidian_links.py rebuild` 把关系区重渲到全部文档，最后 `core_cards.py check` 与 `validate_package.py --mode final`。任何讲义或知识改变时卡片 stale，重新统一整理，不能继续按旧卡片验收。每张卡必须含来源知识和各关联讲义的 canonical WikiLink。完整命令见 [讲义流水线](lesson-pipeline.md)。
