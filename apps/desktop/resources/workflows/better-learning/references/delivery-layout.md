# 交付结构与收尾

教学产物全部生成后，应用工作流把课程整理成可交付形态。收尾分两步：核对转写成员终态和执行 `package`。

## 一、确认转写成员已经结束

`course_workflow assemble-transcription` 成功表示全部来源合成，并且没有仍在写文件的活动尝试。宿主按真实子 Agent 终态收集结果；`complete-stage` 通过转写校验后停止应用内置看门狗。主代理在进入交付阶段前检查原生游标与台账，不手动启动或停止 `watchdog.py`。

`package` 会拒绝仍有活跃租约的台账；旧版课程若仍有旧 `watchdog.py` 进程也会被拒绝。`assemble` 不会在 reserved/running 租约或未完成单元存在时通过。

## 二、package：清理与归置

在 delivery 阶段依次调用 `course_workflow run-step` 的 `package-preview` 和 `package`。随后调用 `complete-stage`；宿主会执行 packaged 校验并核对收据。

先 `--dry-run` 预览将删除与移动的内容，确认后再执行。

**删除**（中间产物，正文已由合成文件承载）：

| 路径 | 说明 |
| --- | --- |
| `_工作区/转写尝试/` | 尝试暂存文件，成功结果已原子提交并合成来源转写 |
| `_工作区/派发提示/` | 成员提示词，一次性 |
| `_工作区/提取内容/` | 逐页渲染图、文本块、单元转写副本、识别证据——**体积主体** |
| `_工作区/office渲染/` | DOCX/PPTX 整页 PNG 缓存；来源与缺字字体报告留在台账中 |

**保留**：`_工作区/` 下的台账与索引（`转写任务.json`、`资料索引.json`、`章节索引.json`、`知识索引.jsonl`、`覆盖台账.jsonl`、`生成进度.json`、`结构检查.json`），供追溯与审计。

**归置**：把报告与说明类 Markdown 移入 `课程文档/`，并按 canonical map 重写 WikiLink，兼容重算旧 Markdown 相对链接。

## 三、最终交付结构

```text
课程包/
├── 开始学习.md              ← 学习者入口
├── 核心知识点.md            ← 卡片
├── 学习文档/                ← 讲义
│   └── 01-第1讲-….md
├── 资料转写/                ← 只保留整合后的完整版
│   └── SRC-001-名称-哈希-agent-v1.md
├── 课程文档/                ← 报告与说明
│   ├── 学习需求.md
│   ├── 学习路径.md
│   ├── 资料清单.md
│   ├── 知识内容.md
│   ├── 质量报告.md
│   ├── 待核实问题.md
│   ├── 学习反馈.md
│   └── 转写拆分计划.md
└── _工作区/                 ← 仅台账与结构检查，无中间产物
```

**外层只放学习者直接要用的三样**：`开始学习.md`、`核心知识点.md`、`学习文档/`；`资料转写/` 作为溯源附件保留整合版。

## 四、体积效果

实测参考包（60 页扫描教材，含 60 个单元渲染图）：

| 项 | 体积 |
| --- | --- |
| `_工作区/`（清理前） | 34.0 MB |
| 全部交付物 | 0.6 MB |
| 过程文件占比 | **98.3%** |

`package` 后包体积约为原来的 1/50。

## 五、打包后的限制

`package` 是**终态动作**：

- 中间产物已按设计删除，`assemble` 等依赖单元文件的操作不再可用；
- `check` 检测到 `packaged` 标记且提取目录已清空时直接返回通过（结构检查结果已存入 `_工作区/结构检查.json`）；
- 如需增补资料，重新走 `inventory` → `prepare` 流程，不要在已打包的包上续接。

## 六、链接安全

`package` 会重算所有学习者可见 Markdown 的相对链接，并保持以下内容不变：

- 围栏代码块与行内代码内的文本；
- 外部链接（`http` / `https` / `mailto` / `data`）；
- 锚点（`#...`）与查询串（`?...`）；
- 指向未被移动文件的链接。

实测（`学习文档/01-第1讲.md` 引用被移动的文档）：

| 原链接 | 打包后 |
| --- | --- |
| `../学习需求.md` | `../课程文档/学习需求.md` |
| `../知识内容.md#k-000001` | `../课程文档/知识内容.md#k-000001` |
| `../核心知识点.md`（未移动） | 不变 |
| `https://x.com/a.md` | 不变 |

**打包前应已通过 `validate_package.py`**——它检查链接可达性，能在移动前发现断链；`package` 只负责搬家，不负责修复本来就断的链接。

新 Obsidian 课程中，`[[知识内容#^K-01]]` 在打包后变成 `[[课程文档/知识内容#^K-01]]`。打包后再次验证双链，并记录纯路径变化的讲义/卡片提交快照；不把路径移动误判为教学内容变化。讲义 staging 也会被清理。

`packaged` 复验的范围是**交付形态**：交付文件齐备、块唯一、每个目标仍可解析、文件未被改动；提取层与覆盖审计属于 `final` 阶段（依赖已被清理的 `_工作区/提取内容`），不在打包后重复。`package` 会在移动与改链之后刷新 `_工作区/链接校验报告.json`，作为打包后的核对基准。

打包必须保留重验所需数据：`_工作区/课程配置.json`、`实体注册表.json`、`链接映射.json`、`链接校验报告.json`、`核心卡片计划.json`、`练习索引.jsonl`、`路径索引.json`、`管理文档索引.json` 与 `事务记录.jsonl` 都不属于中间产物。`package` 收尾后运行 `validate_package.py --mode packaged`：它核对交付文件与 final 快照、目标是否仍能解析、块是否仍唯一；中间产物已清理不影响判定，交付文件内容与快照不一致报 `STALE_MANIFEST`。

## 轻量收尾回执

当前交付采用 metadata-v1。final 完成原有内容和来源验收后，记录交付 Markdown、转录件和关键台账的大小、修改时间、变更时间及文件身份。package 复用通过结果；移动或改链后，只刷新实际改动产物的指纹，检查一次链接并记录新路径和元数据。packaged 只核对清单和元数据，不重复完整语义验收，不全局读取正文计算哈希。学习笔记不使交付回执失效。

这是普通变更检测，不能替代密码学审计。已通过旧打包检查且文件未晚于验收报告修改的包可在下次检查时升级，原快照留存为“链接校验报告.v1.json”。仍在生成的旧哈希快照需重新运行一次 final 后再 package。此机制取代上文按全局哈希核对快照的旧描述。
