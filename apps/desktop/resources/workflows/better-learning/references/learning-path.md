# 学习路径规范

**编写前置门：** 先生成完整、非空的 `知识内容.md`，并运行 `assemble_knowledge.py --course COURSE --check`。未通过不得编写本阶段产物。用户明确要求 AI 补全也必须先建知识库；禁止只凭目录/常识跳过知识库直接写作。


使用 `学习需求.md`、全部知识条目的精简索引和必要章节分片规划。默认生成完整路线，不让考试重点筛选导致知识库内容消失。

规划前按 [学科路由](subject-routing.md) 确定课程默认与各章组合。每章记录主要产出与验证方式：证明/模型、实验记录、程序、史料论证、语言产出、案例判断、作品或操作表现。以知识与能力的真实依赖编排；理论—应用、输入—输出、观察—解释、示范—独立表现等顺序按学科采用。模式改变时间与练习重点，不改变全部来源知识的去向。

1. 为每条可验证学习目标匹配知识和后续练习。
2. 识别必须先掌握的依赖，区别“必要前置”和“有帮助的关联”。必要前置构成有向无环图；循环先判断是否应合并概念或拆出更基础单元。
3. 对已知缺口生成包内补学章节。基础未知者提供诊断分支；基础已证实者可跳过复习，不跳过真正的必要前置。
4. 先按依赖排序，同一依赖层再按由易到难、目标相关性和认知负担排序。源材料章序可以调整，但保留来源映射。
5. 为每章记录目标、先修入口、覆盖知识 ID、教学单元与深度、预计时间范围、目标对应的任务及过关标准、未通过的补学入口及后续章节。先按 [教学粒度规范](teaching-granularity.md) 保存 `_工作区/教学单元.json`，共享情境/方法的知识合组，必要依赖分先后；每个单元写目标、标准、展开触发和停止依据。任务量由目标覆盖决定，不设固定题数。
6. 时间紧时标记“主修 / 选学 / 延后”，保留完整路线和知识去向。不要偷偷省略例题、答案或前置补学。

新课程路径使用链接映射提供的 canonical WikiLink 指向真实文件与稳定块 ID。尚未生成时可在工作计划中记录路径，但交付前必须检查存在。不要链接到不存在的模拟卷、题库、外部课程或卡片；没有相应产物就链接包内实际练习。

知识依赖可用 Mermaid 或关系表展示，必须表达先学方向，不仅画术语树。每章最终目标要能在章内被自测或综合题验证。

时间采用合理范围并说明包括阅读、练习还是复习，不保证每个学生按该时间掌握。复习建议可用当天、第 3 天、第 7 天和考前，根据用户时间调整。

每个 lessons 条目还需包含稳定 L ID、title、order、path，以及本章 path_excerpt；或在学习路径中写带 L ID 的独立标题段落，供调度器只提取本章路径输入。
